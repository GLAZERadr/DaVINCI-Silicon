# 04 — Validation and evaluation roadmap

What has to be true, measured how, before each claim may be made. All numbers come from stored runs; placeholders stay `[LIKE THIS]`.

## 2. Hackathon benchmark (the one experiment that matters)

Design taken from red-team pass 2, which narrows the eight reviewers' proposals.

| Arm | Spec | Start | N | Gates reported |
| --- | --- | --- | --- | --- |
| A | Equation spec (`spec/fifo_spec.md`) | clean | 10 | G1, G2, G3 separately |
| B | Prose spec, written by someone who has not read `rtl/sync_fifo.v`; requirements rewritten the same way | clean | 10 | G1, G2, G3 |
| C | Equation spec | seeded M1…M8, once each | 8 | G2, G3 |
| Baseline | — | seeded M1…M8 | 8 | inverse-mutant search; shown as a ceiling on what seeded repair can prove, not as a race |

**Fixed for every run:**
- Provider `meta`, model `muse-spark-1.3`.
- `max_tokens` ≥ 16k, `reasoning_effort` recorded.
- `--sandbox docker`, one image id.
- No cache reads.

**Cost estimate:** about 30 live runs × $0.03 ≈ **$1** (from `runs/_ledger.jsonl` unit costs). Budget is not the constraint; wall time is, at about 30 s per run, so under 30 minutes.

**Metrics table**, generated by a script from `evidence/*/run.json`, never typed by hand:

| Metric | Definition |
| --- | --- |
| First-pass rate (per arm) | attempt 1 passes G2 **and** G3 / N |
| Green within 3 repairs | runs ending `pass` / N |
| Escape rate | runs passing G2 but failing G3 / runs passing G2 |
| Truncation rate | attempts with `finish_reason != stop` / attempts |
| Attempts to green | mean and median over green runs |
| Time to green | median `time_to_green_s` |
| Cost per run | mean `cost_usd`, from the ledger |
| Sim vs model seconds | median per attempt (supports "simulation is cheap ground truth") |
| Re-simulation reproducibility | replays with matching per-attempt RTL hash and verdict / replays |
| Outcome spread | distribution of attempts-to-green across the N runs of an arm |

Report **Wilson 95 % intervals** for the two N = 10 arms. With N = 10, a 10/10 result has a lower bound of about 0.72. Say so rather than write "100 %".

## 4. Acceptance criteria for P0 and P1

**P0 (before anything public or any benchmark):**

1. **Replay integrity.**
   - Replay reads the source run's `response.md`. Fake never writes shared state.
   - Test: fake → live-shaped → fake → replay of the live-shaped run shows matching RTL hashes.
   - live01 and live02-m1 replay with `reproduced: true`.
2. **G1 closes the bypass.**
   - Fixtures `$fwriteh`, pasted `` $fo``pen ``, `` `include `` and `` `define `` are rejected.
   - The reference RTL and both live RTLs pass.
3. **Pinned hash covers the verdict path.** Changing `verify/run_suite.py` or `verify/mutants.json` aborts a run.
4. **Fail-closed API.**
   - With a live provider and no token, live runs are refused (401 or startup refusal).
   - `compare_digest` is used; `sandbox` is not client-selectable.
5. **No local simulation of model RTL.** `--sandbox local` with `meta`/`baseten` exits with a clear error. The local env is scrubbed of `*_API_KEY`.

**P1 (hackathon MVP):**

6. **Parameter sweep G3.**
   - ≥3 parameter sets including a non-power-of-two DEPTH, with consistent CW. Own pinned hash.
   - Reference passes; hard-coded-width variant fails; sweep output absent from every `prompt.json`.
7. **Static compile gate.** `iverilog -g2001 -Wall` compile-only. An `always_ff` fixture is rejected.
8. **Truncation and stop states.**
   - `max_tokens` ≥ 16k; `finish_reason != stop` → `truncated`.
   - Identical RTL twice → `no_progress`; exhaustion → `needs_engineer`.
   - Repair after a rejection includes the last simulated RTL.
9. **Mutation evidence bound to the suite.** `mutation.json.suite_sha256` exists; the board hides the score if it doesn't match.
10. **Interface guard.** A spec or requirements with other params or ports yields `not_verifiable`, never pass or fail.
11. **Honest labels.**
    - The README and board say "suite mutation score vs reference (8 hand-written mutants)", "re-simulation reproducibility", "spec includes reference equations (arm A)".
    - The `grep -rniE "world model|physical ai|digital twin"` check passes over README, UI and the video script.
12. **Benchmark run and committed.** Arms A, B, C + baseline. Table generated from `evidence/`. Every attempt counted.
13. **Evidence Board.** Renders from the committed bundle with no network access to the model; replay works.

## 5. Post-hackathon validation (product hypothesis)

| Step | Question | Method | Kill or continue signal |
| --- | --- | --- | --- |
| V-1 | Is verification evidence the pain? | 5–10 interviews (DV leads, CAD, RTL, faculty) | <3 name it as a cost they would pay to cut → rethink (see `06`) |
| V-2 | Can a block from outside the team be onboarded? | one design partner's block plus their tests | onboarding effort vs writing the RTL by hand |
| V-3 | Does generation work on a harder block? | AXI-Stream skid buffer or round-robin arbiter; prose spec; formal properties | green within 3 repairs vs a template baseline |
| V-4 | Can AI draft oracles independently? | model drafts properties/golden model from prose, separately from the RTL; measure shared-misreading rate | shared wrong behaviour rate |
| V-5 | Standard benchmark | a CVDP subset (arXiv 2506.14074) | compare against published pass@1 |
